## [Unreleased]

### Changed · 2026-10-03 性能、人口概览与事件节奏

- 超过默认300人阈值后，真正停止个人头像和详情展示，清空选择，切换为4张阶层汇总卡。低于阈值恢复个人模式。截图试玩发现中等窗口宽度的旧详情栏挤压卡片，已改为群体模式单栏容器并补回归。
- 个人履历上限由120缩为界面实际使用的12年；超过人口阈值不记录并释放个人履历。国家历史最多240年，叙事钩子30条，战争历史40条；旧存档加载与保存均裁剪超长记录，当前模拟数据不删减。
- 商品交易改为稳定最小堆选取缺粮工人；儿童赡养改为线性选取捐粮者，保持同阶层、最多余粮和同值顺序规则。120组经济状态逐人精确匹配原算法，交易粮食与产品守恒。
- 23张事件均明确分类：橙色好事件、黑色坏事件、灰色中性事件；弹窗、日志、图例使用颜色+文字+符号。小程序视图不再传递事件内部隐藏值或执行函数。
- 新增乡里丰年会、巧匠献礼，两种奖励择一，无须额外掏钱。连续3次非好事件后下一次普通事件保底为好事件，继续避开最近两张卡；计数随存档保留，空白年份不消耗，战争与已打开事件不会被覆盖。
- 保留默认低分可持续经营、1.6/2秒可跳过过渡，以及善恶/理性仅记录不应用的设计。

#### 复测结果

- 本机固定人口压力场景：2000人交易+赡养中位耗时约294.2ms → 1.3–1.4ms；单年约325ms → 4–5ms。数值为本机测量，不承诺所有设备相同耗时。
- 相同压力场景存档11702KiB → 384KiB，个人履历240000条 → 0；构造同等旧履历并强制GC后，V8保留堆约9.75MiB → 3.27MiB（不是浏览器进程总内存）。
- 默认策略、100个混合种子×150年：100局存续，最终评分38–51分；另外100局产生7870次事件，645次触发喜讯保底，含反复存读档。600年长局记录有界。
- 网页、小程序核心和单文件12个种子×120年逐年一致；8套浏览器回归覆盖60回合游玩、真实按钮推进、离线运行、300/301/2000人切换、手机布局、三色日志、加载过渡与取消。
- 性能复测命令及断言见README。浏览器虚拟时间用于交互测试，不作为性能测量依据；耗时以Node高精度计时器测量。

#### 设计依据与取舍

- 借鉴Valve《Left 4 Dead》开发演讲中的压力与喘息交替：本作采用简单的事件次数保底，不复制动态战斗导演，也不暗改战争结果。出处：[Michael Booth, The AI Systems of Left 4 Dead，第77–81页](https://steamcdn-a.akamaihd.net/apps/valve/2009/ai_systems_of_l4d_mike_booth.pdf)。
- 分类不仅靠颜色，同时保留符号与文字，参考[Xbox无障碍指南103](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/103)。
- 当前优先保证可读性、节奏起伏和有意义的奖励取舍；暂不增加大图依赖或复杂顾问系统，保持零依赖、离线可玩与低内存成本。

### Changed · 2026-10-01 数值与节奏优化

- 扩大复核到100个非相邻随机开局、150年：基础经营全部存活（36～46分），包含事件和签约的经营也全部存活（38～52分）。测试脚本支持指定种子数量、年限与混合种子。
- 低工资提示说明积蓄下降及旧存档保留政策；不会悄悄覆盖玩家设置。单文件版快进保留中间每一年的日志，便于追查人口和国库变化。

- 修复库存税、默认欠薪、儿童独立缺粮、单名治安官零处理能力和公务员空缺不补录的循环性衰退。
- 交易按库存补货并逐笔同步结算，优先采购缺粮工人的商品，保留基本口粮；没有商人时可直接成交。
- 默认工资调整到 20；事故死亡率调整到 0.3%；开局男女均衡，生育和阶层晋升保留必要的人口结构。
- 满意度加入生活水平回归，保留高低满意度犯罪风险；战争年概率改为 8%，至少间隔 10 年。
- 增加 0～100 治理评分（储备35%、满意35%、人口20%、智力10%），低评分不触发失败；原隐藏人格值仍仅记录、不应用、不显示。
- 年度推进加入场景与进度条：普通约1.6秒、快进整批约2秒，支持跳过、忙碌锁定、异常释放和小程序离页取消。
- 核心模拟统一生成小程序镜像和单文件包；存档保留失败计数与结束状态，兼容旧单文件事件编号。
- 回归：三组各40个随机开局（无事件战争、事件+签约、事件+标准出兵）均完成120年；三端12个种子逐年结果一致；网页连续60回合、离线单文件、390px布局、过渡时长与异常恢复检查通过。

### Added

- 增加事故、饥饿与年龄三类年度死亡，并加入固定 1% 事故死亡率。
- 人口增加性别与育龄男女配对生育，加入资源/人口压力软上限和头像渲染上限。
- 增加黑死热、赤风流感、灰斑疫；个人资产会降低瘟疫致死率，疫情可定量损失财产。
- 税务官每人最多管辖 100 名纳税人；公务员配额旁增加作用说明。
- 公务员说明改为逐岗位展示；民生官员第 11 年、军事官员第 21 年解锁。
- 人口超过 100 后，税率调整由民生官员数量决定：0 人锁定、1 人间隔 10 年、逐人递减至每年可调。
- 恢复低/高满意度犯罪概率、前五年保护期、偷窃与治安官从良/移除机制。
- 随机事件扩展至 21 张；所有选项均同时具有实际收益与代价，查办贪官、惩办商人、接纳灾民会真实改变人口结构，并新增贪腐余波、商路萧条、新民安置、从良者复审四条两年后连锁事件。
- 增加仅在内部状态与存档中记录的善恶值、理性值；所有事件选项均会改变两项数值，暂不参与玩法判定或界面展示。
- 增加可调公务员人均工资，年度总工资按在职公务员人数结算；旧存档自动补默认工资。
- 农民和工人的单人年产量分别保底为单人年粮食/产品消费的 13 倍，高于保底的原产量不变；商贸改为按原始策划案的集合进货、官员固定加价和农村阶梯议价顺序逐利成交。
- 增加休养生息、均衡治理、富国强兵三种一键政策方案，原有税率、公务员与军费滑块收纳为可展开的高级调控。
- 增加“推进至决策”和年度变化摘要；自动推进会在事件、战争、政策窗口或游戏结束时停下。
- 事件抽取避开最近两次结果；年度日志改为同年更新而非重复追加，当前日志、年度摘要与最近事件支持存读档。

## [0.1.0] - 2026-05-22 · 首发可玩版

### ✨ Added 新增

- **核心模拟引擎** `packages/core`（平台无关，ES Module）
  - 人口模型：年龄 / 阶级 / 财富 / 学识 / 出生死亡
  - 经济模型：农产 / 工产 / 贸易 / 价格弹性
  - 社会模型：6 阶级满意度 / 治安 / 抢劫 / 阶级流动
  - 政府模型：5 类公务员任命 / 累进税 / 教育 / 军事
  - 8 张随机事件卡：旱灾、瘟疫、起义、商队、外敌、流星雨、清官、丰年
  - 章节系统：立国 / 守成 / 中兴 三章不同胜负条件
- **Web 网页版** `apps/web`
  - 中式水墨风 UI（朱砂 + 米白 + 圆点纸纹）
  - 自绘 Canvas 阶级饼图 + 历年人口/国库/治安曲线
  - 三栏布局：政策面板 / 阶级图表 / 朝堂日志
  - 事件弹窗、结算弹窗、新手引导
  - 存档：localStorage 自动保存
- **微信小程序版** `apps/miniprogram`
  - 三页面 TabBar：执政首页 / 政策 / 关于
  - 核心逻辑 CommonJS 镜像，与 Web 端共享算法
- **GitHub Pages 自动部署** `.github/workflows/pages.yml`
- **完整文档** `docs/`
  - 改进版策划案（v2）
  - 玩家视角游戏说明
  - 部署与推广指南

### 🔧 Changed 变更

相对于原始策划案 v1（用户提供的 docx）的改进点：

- **修复死亡概率公式除零 bug**：`1 - 1/(age - 49)` → `1 - 1/max(age - 50 + 1, 1)`，并加 `hardCap = 90`
- **缩放贫富差距惩罚参数**：原始 `atan(18*x)` 过陡，缩放为 `atan(1.8*x)` 使曲线平滑
- **产品需求函数 clamp**：避免负值，下限钳制为 0
- **新增 Game Loop 三阶段**：原案缺失，补全任命 → 结算 → 决策循环
- **新增章节胜负条件**：原案无终局判定
- **新增事件系统**：原案完全缺失，补充 8 张随机事件卡
- **新增 UI/UX 设计**：原案无界面草图，补充三栏布局与水墨配色规范
- **新增新手引导**：3 步首次启动指引
- **新增存档/设置**：localStorage + 设置面板
- **新增美术 / 音效定位**：极简水墨纯 CSS 方案
- **新增竞品分析**：Reigns / Tropico / 模拟城市
- **新增商业化方案**：免费 + 广告 / 章节解锁
- **新增性能上限**：人口规模 ≤ 1000，分帧结算

### 🐛 Fixed 修复

- 修复 PowerShell + Python 重定向编码乱码问题（脚本内直接写 UTF-8）
- 修复跨包 import 在小程序不可用问题（提供 CJS 镜像）
- 修复 GitHub Pages 部署 monorepo 路径问题（根目录跳转 + `.nojekyll`）

### 📦 Project Structure 工程结构

按互联网大厂 Monorepo 规范组织：

```
packages/  → 平台无关核心包
apps/      → 各端宿主壳（web / miniprogram）
docs/      → 文档中心
.github/   → CI/CD
```
