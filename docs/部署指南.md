# 部署指南

本文档介绍把《小国执政官》部署到 **GitHub Pages** 与 **微信小程序** 两种途径，分别面向「面向公众展示」与「微信生态分发」两种诉求。

---

## 方案一：GitHub Pages（最简单，5 分钟上线）

### 适用场景
- 想把作品当作品集展示给面试官 / 朋友
- 不想注册任何额外账号
- 0 元、0 服务器、自带 HTTPS

### 步骤

#### 1. 创建 GitHub 仓库
```bash
# 在本目录初始化 Git
cd D:/游戏求职/策划案/小国执政官
git init
git add .
git commit -m "feat: 初始版本 v0.1"
```

到 https://github.com/new 创建一个**公开仓库**，例如名字叫 `xiaoguo-zhizhengguan`。

#### 2. 推送代码
```bash
git remote add origin https://github.com/<你的用户名>/xiaoguo-zhizhengguan.git
git branch -M main
git push -u origin main
```

#### 3. 启用 GitHub Pages
打开仓库 → **Settings** → **Pages**：
- Source 选择：`GitHub Actions`
- 等待 2 分钟，工作流会自动跑（仓库已经写好 `.github/workflows/pages.yml`）

#### 4. 访问游戏
部署成功后访问：
```
https://<你的用户名>.github.io/xiaoguo-zhizhengguan/
```
根目录的 `index.html` 会自动跳转到 `apps/web/`，正常进入游戏。

#### 5. 后续更新
本地改完 → `git push` → 工作流自动重建 → 秒级更新。

#### 自定义域名（可选）
- 在仓库根目录新建 `CNAME` 文件，写入你的域名（如 `xiaoguo.example.com`）
- 在域名服务商处配置 CNAME 解析 → `<你的用户名>.github.io`

## 方案二：微信小程序（流量大，需要资质）

### 适用场景
- 想触达 10 亿微信用户
- 朋友圈分享、群分享传播
- 后续接入广告变现

### 0. 整体流程
```
注册小程序账号 → 下载开发者工具 → 导入 apps/miniprogram → 调试
→ 真机预览 → 上传代码 → 提交审核 → 发布
```

### 0.1 上线前文件与材料清单
- 小程序账号与 AppID：在微信公众平台注册后取得，填入 `apps/miniprogram/project.config.json`
- 项目源码：导入目录选择 `apps/miniprogram/`
- 名称、简介、头像、服务类目：个人主体建议避开强游戏类目，可定位为“模拟器 / 策划验证工具”
- 图标与截图：准备 1024×1024 头像、至少 3 张核心玩法截图，用于提审与介绍页
- 隐私与用户协议：若只用本地存档，可写明不采集个人信息；如后续接入登录、排行、广告，需要补隐私协议
- 版本说明：例如 `0.2.0`，备注“立国章节、默认数值平衡、本地存档”
- 合规材料：若以“游戏/小游戏”正式发行，通常需要企业主体、软著、版号等材料；个人主体更适合先做工具/模拟器内测

### 1. 注册账号
- 打开 https://mp.weixin.qq.com/cgi-bin/wx_open_register
- 主体可选：**个人**（最快、免费、无需公司资质）
- 注册完成后获取 **AppID**（形如 `wx1234567890abcdef`）

### 2. 修改 AppID
打开 `apps/miniprogram/project.config.json`，把：
```json
"appid": "wxxxxxxxxxxxxxxxxx"
```
改成你的真实 AppID。

### 3. 下载并打开开发者工具
https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html

打开后选择「**导入项目**」，目录选 `apps/miniprogram/`。

### 4. 本地调试
- 工具会自动编译并显示模拟器
- 开发者工具的「真机调试」可以扫码用手机预览
- 修改代码立即热更新

### 5. 上传与提审
- 在工具右上角点击「**上传**」，填写版本号（如 `0.1.0`）和备注
- 进入 mp.weixin.qq.com 后台 → 「**版本管理**」→ 找到刚上传的版本 → 「提交审核」
- 审核 1~7 天，过审后点「发布」

### 6. 个人主体的限制（重要）
- **不能**接虚拟支付、不能涉及游戏付费、不能涉及医疗金融教育等敏感类目
- 「游戏」类目个人主体已**关闭**注册；建议选择 **「工具 / 效率」** 类目，名称可叫《小国模拟器》《策划案验证器》之类
- 真要上"游戏"类目，需要企业主体 + 文化经营资质 + 软著

### 7. 推荐替代方案：小游戏
如果想堂堂正正以"游戏"名义上线：
1. 申请 **微信小游戏**（不是小程序）
2. 把代码迁到小游戏目录结构（用 Canvas 渲染）
3. 申请文网文 / 软著 / 版号（个人比较难）

## 方案三：兼容两端的工程化建议（进阶）

如果你后期想**一份代码两端发布**，推荐三选一：

| 方案 | 优势 | 劣势 |
|---|---|---|
| **Taro 4** | 京东出品，主流 | 学习曲线 |
| **uni-app** | DCloud 出品，文档多 | 性能略弱 |
| **手写适配层** | 极简、可控 | 维护成本高 |

本仓库当前采用「**手写适配层**」：
- `packages/core/` 是 ES Module，纯 JS 不依赖任何环境
- `apps/web/` 直接 import `packages/core`
- `apps/miniprogram/core/` 是 CJS 镜像（小程序不支持跨包 import）
- 修改核心逻辑时保持两份同步

> 团队化后，建议升级为 Taro 或 uni-app，自动一份代码出三端（H5/小程序/App）。

## 方案四：其他平台（一句话）

| 平台 | 操作 |
|---|---|
| **Vercel** | `vercel deploy` 直接出网址，比 Pages 快 |
| **Netlify** | 拖拽 `apps/web/` 文件夹即上线 |
| **GitCode Pages** | 国内访问更快，操作类似 GitHub |
| **腾讯云静态托管** | 适合小程序后台联动 |
| **抖音小游戏** | 字节生态，需要企业主体 |
| **QQ 小程序** | 提审较松，转化年轻用户 |

## 常见坑

| 问题 | 解决 |
|---|---|
| GitHub Pages 部署后 404 | 确认 `.nojekyll` 文件存在；URL 区分大小写 |
| 小程序 import 报错 | 小程序不支持 ES Module 跨包 import，必须用 require |
| iOS 微信白屏 | 检查 ES2020 语法兼容（小程序基础库 ≥ 2.20.0） |
| GitHub Action 失败 | 进 Settings → Actions → 允许工作流写权限 |

如还有问题，欢迎提 Issue 🙌
